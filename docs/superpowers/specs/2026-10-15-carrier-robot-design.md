# ノーツ運搬ロボット 設計書

- 作成日: 2026-10-15
- 対象大会: 千葉大学ロボットコンテスト 2026(2026-10-31)
- 状態: 設計確定(実装計画前)

## 1. 目的と役割

### 1.1 目的

千葉大学ロボコン 2026 において、自チームのノーツ(15cm 立方体の段ボール箱、約200g)をノーツゾーンからゴールゾーンまで運搬する差動2輪ロボットを製作する。

### 1.2 このロボットが行うこと

- ノーツゾーンで、壁際に並んだノーツを **2個同時に** 把持する。
- スラロームゾーンを通過してゴールゾーンまで運ぶ(スラローム内の保持上限は2個。ルール 2.4.3)。
- ゴールゾーンの床に箱を置き、別機体に引き渡す。

### 1.3 このロボットが行わないこと

- ビンゴ(棚)への設置。別機体の役割。
- 妨害、および妨害権のチャージ。妨害機は別機体とする(ルール 2.6.2、2.6.4 により、チャージは妨害機自身の往復のみ有効と解釈)。

### 1.4 成功基準

- 大会当日、USB 有線の手動操縦で、箱2個をノーツゾーンからゴールゾーンまで確実に運べる。
- スラロームの木枠側面に意図的に接触せずに通過できる(ルール 3.3、Q21)。
- 非常停止ボタンで即座に停止できる(ルール 7.1)。

### 1.5 将来拡張(大会スコープ外だが配慮する)

- 自動走行:エンコーダと側面の超音波センサーによる壁沿い走行。ハードウェアとファームウェアの土台は今回用意する。
- 無線化:USB と同一パケットを UART に流せるようにしておく。

## 3. 全体構成

- 足回り:差動2輪+後部ボールキャスター
- 把持:左右対称に開閉するアームで、箱2個を横から挟む

- 操縦:PC につないだゲームパッド → PC 側プログラム → USB(アイソレータ経由)→ Bluepill

## 4. 機構設計

### 4.1 方針

- 加工は **アルミ材と3Dプリンタのみ**。卓上 CNC は極力使わない。
- CAD は build123d(Python)。寸法は `mechanical/params.py` に集約する。

### 4.2 足回り

- 20mm 角アルミフレームで約 280(幅)× 250mm の枠を組む(側面の超音波センサー込みで閉じたときの幅を 320mm 以内にするため、当初の 300mm から縮めた)。駆動輪は枠の内側に入れる。底板は使わず、3Dプリントのブラケットで部品を直接固定する。
- 駆動輪2個(直径 65mm、4mm D カット軸用カップリング)を左右中央よりやや前に配置する。
- 後部にボールキャスター1個。
- 駆動モーター:JGA25-370、12V、エンコーダ付き、無負荷約 300rpm。

#### 駆動の所要性能(根拠)

- 前提:機体約 2.5kg、箱2個 0.4kg(床との摩擦係数 0.5 で引きずり抵抗約 2N)、最高速度 1.0m/s、加速度 1.5m/s²、車輪直径 65mm。
- 必要な力:加速 約4.4N + 箱 約2N + 転がり 約0.6N ≒ 7N(1輪あたり 3.5N)。
- 1輪あたりトルク:常用 約0.11N·m。安全率2で、常用 0.12N·m 以上、停止トルク 0.3N·m 以上を目安とする。
- 車輪が滑り出すのは約 0.26N·m(1輪荷重 約10N、ゴムの摩擦係数 0.8)。これを超えるトルクは不要。
- 回転数:1.0m/s に約 290rpm が必要。負荷時の低下を見込み、無負荷 300〜350rpm とする。

### 4.3 把持機構

- ラック2本は、ピニオンの近くで枠に固定した3Dプリントのガイドブロック(片側2個)の中を滑らせる。固定レールにすると閉じても幅がレールの長さ(約420mm)のまま残るため、レールは使わない。ラックはアームより上(床から 140〜152mm)を通し、閉じたときに反対側のアームの上を越えられるようにする。
- ピニオン1個でラック2本を逆向きに動かし、左右のアームを対称に開閉する。
- アームは前方へ約 170mm 伸び、内側の床から約 30〜120mm の高さにゴム付きパッドを付ける。
- ストローク:開いたとき内側 約400mm(箱2個と隙間の合計 348.5mm に余裕を足す)。閉じきりで約130mm(箱1個も把持可能。箱幅より狭くして、空のときと箱1個のときを位置で区別できるようにする)。箱2個を挟むと約300mm。
- ガイドブロックは3Dプリントのデッキ(厚さ3mm)に載せ、デッキはフレーム前端の横材に立てた 20mm 角アルミの柱2本(長さ約84mm)で支える。把持モーターはデッキの下面に付け、ピニオンの下側のハブ(φ14 × 5mm)がデッキの穴を通ってモーター軸を受ける。
- 開閉の両端は機械的に止める。開ききりはラック背面のストッパーがガイドブロックに当たる位置、閉じきりはアームのブラケットがガイドブロックの端に当たる位置。リミットスイッチは使わない。
- 箱は持ち上げず、床を滑らせて運ぶ。
- 壁際の箱にも、横から挟むため壁と干渉しない。

#### 歯車

- モジュール1、ピニオン 20歯(ピッチ半径 10mm)、歯幅 約12mm、PETG で3Dプリントする。20歯未満にはしない(切り下げを避ける)。
- 歯の強度:15N 程度の歯面荷重で歯元応力は約 5MPa。PETG の強度に対して十分な余裕がある。
- 軸の固定:印刷穴を D カット軸に直接はめない。M3 ナットを埋め込み、イモネジで D カットの平面を押さえる。または真鍮ハブを使う。

#### 把持モーターと所要性能

- 把持モーター:JGA25-370、12V、エンコーダ付き、無負荷約 100rpm。N20 は歯車箱の強度が不足するおそれがあるため使わない。
- 挟む力の目標:片側 10N。保持力は 2面 × 摩擦係数 0.8 × 10N = 16N で、箱2個の引きずり抵抗 約2N に対して約8倍の余裕。
- 所要トルク:ピニオンは左右2本のラックを同時に押すため、2 × 10N × 0.010m ÷ 効率0.7 ≒ 0.29N·m(停止時)。
- 開閉時間:片側 125mm はピニオン約2回転。約100rpm で約1.2秒。

#### 制御方式(ストール把持)

- 弱い力でモーターを回し、箱に当たって止まった状態で保持する。
- 挟む力はモーター電流の上限で決める。ハードウェア側では DRV8871 の電流上限抵抗(約1A)で制限し、ファームウェア側でも PWM の上限で制限する(二重の制限)。
- 実際の挟む力は、組み立て後にばねばかりで測定して調整する。

### 4.4 センサー配置

- 超音波センサー HC-SR04 を左右の側面に2個ずつ(前寄り・後ろ寄り、間隔は約200mm)、床から約45mm の高さに付ける。前面には付けない。
- 2個の距離の差から壁に対する傾きを求める。

### 4.5 その他

- 非常停止ボタンは上面の後方、押しやすい位置に付ける。
- USB ケーブルは後方から出し、引っかからないよう固定する。

## 5. 電気設計

### 5.1 電源系統

1. LiPo 3S → XT60 → 平形ヒューズ 10A → メインスイッチ → 非常停止ボタン(NC 接点。電源ラインに直列で、全電源を遮断する)
2. その先で次の2系統に分ける。
   - モーター系:バッテリー電圧を直接 DRV8871 × 3 に供給する。電源ラインに 470µF/25V の電解コンデンサを付ける。
   - 5V 系:降圧モジュール(MP1584、5.0V に調整)から、超音波センサー4個に直接供給する。Bluepill 5V ピンにはショットキーダイオード(SS34 など)を通して供給する。

- 3S を選ぶ理由:JGA25-370(12V)と電圧が合う。4S 以上は停止時の電流と発熱が増えるだけで利点がない。5分の試合での消費は約 170mAh の見込みで、容量は 1000〜2200mAh で足りる。
- ショットキーダイオードは、Bluepill の 5V ピンが USB VBUS と直結していることによる PC への逆流を防ぐためのもの。
- 3.3V は Bluepill のオンボードレギュレータで作る。負荷はマイコン約50mA とエンコーダ3個約45mA。
- 電線は電源系 16〜18AWG。

### 5.2 USB 接続

- PC と Bluepill の間に USB アイソレータ(ADuM3160、12Mbps 対応品)を入れる。モーターのノイズによる USB の切断を防ぎ、PC を保護するため。
- ケーブル長は 3〜5m(USB 規格上限 5m)。
- Bluepill の USB プルアップ抵抗(R10)の誤実装に備え、PA12 と 3.3V の間に 1.8kΩ を後付けできるパッドを基板に設ける。

### 5.3 モータードライバ

- DRV8871 モジュール × 3(駆動用2、把持用1)。電源電圧は 6.5〜45V、入力の High 判定は 1.5V 以上で、3.3V の信号で駆動できる。
- 駆動用の電流上限はモジュール既定(約 2.1A)のまま使う。
- 把持用は、電流上限抵抗を約 62kΩ(上限約1A)に付け替える。付け替えできない品の場合は、ファームウェアの PWM 上限だけで制限する。
- 各モーターの端子間に 0.1µF のセラミックコンデンサを付ける。モーターの配線はねじって引き回す。
- 駆動方式:1モーターあたり PWM 2本(IN1、IN2)。オフ区間がどちらの向きでも「ブレーキ」になるように制御する(片側を High 固定、もう片側に反転した PWM を入れる)。これにより、前進と後進で PWM の値と速さの関係がそろう。PWM 周波数は 20kHz。

### 5.4 ピン割り当て(STM32F103C8)

| 機能 | ピン | 周辺機能 |
|---|---|---|
| 左モーター IN1 / IN2 | PB6 / PB7 | TIM4 CH1 / CH2 (PWM) |
| 右モーター IN1 / IN2 | PB8 / PB9 | TIM4 CH3 / CH4 (PWM) |
| 把持モーター IN1 / IN2 | PA8 / PA9 | TIM1 CH1 / CH2 (PWM) |
| 左エンコーダ A / B | PA0 / PA1 | TIM2 エンコーダモード |
| 右エンコーダ A / B | PA6 / PA7 | TIM3 エンコーダモード |
| 把持エンコーダ A / B | PB3 / PB4 | EXTI3 / EXTI4(ソフトで4逓倍デコード) |
| 超音波 送信トリガー 前寄りペア / 後ろ寄りペア | PB0 / PB1 | GPIO 出力 |
| 超音波 受信 左前 / 右前 / 左後 / 右後 | PB12 / PB13 / PB14 / PB15 | EXTI15_10(5V 耐性ピン、1kΩ 直列) |
| 電池電圧 | PA4 | ADC12_IN4(47kΩ / 10kΩ 分圧、0.1µF) |
| USB D− / D+ | PA11 / PA12 | USB |
| SWD | PA13 / PA14 | SWDIO / SWCLK |
| 状態 LED | PC13 | オンボード LED |
| 将来の無線用 UART | PA2 / PA3 | USART2 |
| 将来の I2C | PB10 / PB11 | I2C2 |
| 空き | PA5, PA10, PA15, PB5 | |

- PB3 と PB4 を使うため、JTAG を無効化し SWD のみ有効にする。
- エンコーダは 3.3V で給電し、信号を 3.3V にする(PA0、PA1、PA6、PA7 は 5V 非耐性)。エンコーダは 3.3〜5V 対応品を選ぶ。
- HC-SR04 は 5V で給電する。トリガーは 3.3V 出力で動作する。受信信号の 5V は 5V 耐性ピン(PB12〜15)で受ける。
- 電池電圧の分圧点は非常停止より後ろにつなぐ。こうすると、0V になったことから非常停止を検知できる。3S 満充電(12.6V)のとき約 2.2V。

### 5.5 基板

- 大会版は **ユニバーサル基板**(約 100 × 80mm 以上)に手配線で作る。基板上の部品は Bluepill 用ソケット、コネクタ、ダイオード、抵抗、コンデンサだけで、ほぼ1対1の結線(約50本)のため。発注待ちのリスクもなくなる。
- 回路図は KiCad で作り、kicad-cli の ERC で誤りを確認する。プリント基板の設計と発注は大会後の次版で行い、この回路図を使い回す。
- ユニバーサル基板の部品配置(2.54mm 格子の座標)と結線表を文書にし、配線とテスターによる導通確認はこれに沿って行う。
- バッテリーからドライバへの太い電源線は基板を通さず、ネジ端子間を直接配線する。
- 配線はすずめっき線またはポリウレタン線で短く引き回し、コネクタはホットボンドで補強する。
- Bluepill はピンソケットに差し込む。DRV8871 モジュールと降圧モジュールは基板に載せず、ケーブルでつなぐ(部品の到着前にピン配置を確定できないため)。
- コネクタ:電源入力と各ドライバへの電源出力はネジ端子(5.08mm)。ドライバへの信号は XH 3P(IN1、IN2、GND)、エンコーダは XH 4P(3.3V、GND、A、B)、超音波センサーは XH 4P(5V、TRIG、ECHO、GND)、降圧モジュールは XH 4P(VBAT、GND、5V、GND)。予備の UART と I2C 用の端子も設ける。

## 6. ファームウェア設計

### 6.1 構成

- Rust no-std、ターゲットは `thumbv7m-none-eabi`。
- フレームワーク:RTICX(`rticx-cortex-m`)。
- HAL:`stm32f1xx-hal`。USB は `usb-device` と `usbd-serial`。デバッグ出力は `defmt` と `probe-rs`(ST-Link 経由の RTT)。
- クレートは2つに分ける。
  - `robot-core`(no_std ライブラリ):ハードウェアに依存しない処理をすべて入れ、PC 上で `cargo test` を実行する。
  - `firmware`:周辺機能の設定と RTICX のタスク定義を入れる。処理は `robot-core` を呼ぶ。

### 6.2 タスク

| タスク | 種類 | 周期・きっかけ | 内容 |
|---|---|---|---|
| USB 受信 | ハードウェアタスク(USB_LP_CAN_RX0) | 割り込み | 受信バイトをデコーダに渡し、完成したパケットを最新の指令として共有データに書く |
| 超音波 受信 | ハードウェアタスク(EXTI15_10) | 割り込み | 受信信号の立ち上がりと立ち下がりの時刻(DWT サイクルカウンタ)を記録する |
| 把持エンコーダ | ハードウェアタスク(EXTI3、EXTI4) | 割り込み | 4逓倍でデコードしてカウントする |
| 制御ループ | 非同期タスク | 100Hz | 指令タイムアウトの判定、駆動 PWM の更新(加減速制限付き)、把持の状態管理、電池電圧と非常停止の判定 |
| テレメトリ送信 | 非同期タスク | 20Hz | 状態を PC に送る |
| 超音波 トリガー | 非同期タスク | 約15Hz × 2 ペア | 前寄りペアと後ろ寄りペアを交互に鳴らす(左右は同時) |

### 6.3 通信プロトコル

- フレーミングは COBS(区切り 0x00)、誤り検出は CRC-8。USB CDC と UART で同じ形式を使う。
- PC → ロボット(指令、50Hz):連番、前進量(i16)、旋回量(i16)、把持指令(開く / 閉じる / 保持 / 停止)、フラグ(低速モード、非常停止解除要求)。
- ロボット → PC(テレメトリ、20Hz):連番、電池電圧(mV)、各エンコーダのカウント、把持の状態と推定箱数、超音波4個の距離(mm)、非常停止の保持状態、異常フラグ。
- 具体的なバイト配置は `robot-core` の型定義を正とする。PC 側も同じクレートを使うので、二重定義はしない。

### 6.4 安全動作

- **指令タイムアウト:** 最後の有効な指令から 200ms 経つと、駆動モーターをブレーキで停止する。把持は保持を続ける(箱を落とさないため)。
- **起動時:** 新しい指令を受け取るまで駆動しない。
- **非常停止の保持:** 電池電圧が約 0V になったら非常停止として保持し、PC から解除要求が来るまで全モーターを停止したままにする。USB アイソレータ経由でマイコンが動き続けていても、解除した瞬間に動き出すことはない。
- **電池保護:** 10.5V 未満で出力を最大 50% に制限し、警告フラグを立てる。9.9V 未満で停止する。
- **MCU のリセット時:** DRV8871 の入力は内部プルダウンで Low になり、モーターは空転状態になる。

### 6.5 足回り制御

- 大会版は開ループ制御:前進量と旋回量を左右の PWM に配分し、加減速を制限する。
- エンコーダはテレメトリ用に常時読む。速度制御とオドメトリは将来の自動化で使う。

### 6.6 把持の状態管理

- 状態:未原点 → 開動作 → 開(待機)→ 閉動作 → 保持。開動作と閉動作はいつでも切り替えられる。
- 原点合わせ:起動後の最初の開動作で、開き側のストッパーに当たって止まった位置を原点(開ききり)とする。
- 止まった判定:エンコーダのカウントが 100ms 変化しなければ停止とみなす。
- 閉動作:決めた PWM で閉じ、止まったら保持用の弱い PWM に切り替える。
- 箱数の推定:保持に入ったときの位置から、0個(閉じきり)、1個、2個を判定する。
- 時間制限:開動作と閉動作が一定時間で止まらなければ、異常フラグを立てて停止する。

## 7. PC 側操縦プログラム

- Rust で作り、`robot-core` を共有する。ゲームパッドは `gilrs`、シリアル通信は `serialport` で扱う。
- 操作の割り当て(既定):左スティックの上下で前進・後退、右スティックの左右で旋回。把持の開くボタンと閉じるボタン、低速モードの切り替え、非常停止の解除。割り当ては設定ファイルで変更できる。
- 50Hz で指令を送る。USB が切断されたら自動で再接続する。
- 端末に状態を表示する:通信状態、電池電圧、把持の状態と箱数、非常停止の状態、超音波の距離。
- テレメトリを CSV に記録する。

## 8. リポジトリ構成

```
docs/
  superpowers/specs/      設計書
  rules.md                ルールの要点
  wiring.md               ピン割り当てと配線
  tuning.md               調整手順(把持力、電池のしきい値など)
  checklist.md            大会当日の確認リスト
mechanical/               build123d(Python)
  params.py               寸法の集約
  parts/                  部品ごとのスクリプト
  assembly.py             組立て
  tests/                  外形と干渉の確認(pytest)
electrical/               KiCad プロジェクト(回路図)
  scripts/                回路図の生成と kicad-cli による ERC
  perfboard.md            ユニバーサル基板の部品配置と結線表
firmware/
  robot-core/             no_std ライブラリ(PC 上でテスト)
  host/                   PC 側操縦プログラム
  firmware/               STM32 向け(RTICX)。別ワークスペースとし、robot-core を相対パスで参照する
```

- STEP、STL などの生成物はリポジトリに入れず、スクリプトで生成する。
- `robot-core` と `host` は1つの Cargo ワークスペース、`firmware` は別のワークスペースとする(ビルド対象が異なるため)。

## 9. テスト方針

| 対象 | 方法 | 主な確認内容 |
|---|---|---|
| robot-core | `cargo test`(PC) | パケットを作って解析し直すと元に戻る、CRC 誤りの検出、200ms タイムアウト、非常停止の保持と解除、左右モーターへの配分と飽和、PWM の極性(ブレーキ側のオフ区間)、把持の状態遷移と停止判定、箱数の推定、電池のしきい値 |
| host | `cargo test` | 操作の割り当てから指令への変換 |
| firmware | `cargo build --release`(thumbv7m) | ビルドが通ること、バイナリサイズ(64KB 以内) |
| mechanical | `pytest` | 開いたときの外形 ≤ 500 × 500mm、閉じたときの幅、アームと車輪・フレームの干渉なし、ストローク |
| electrical | kicad-cli ERC、回路図と結線表の一致確認 | エラー 0、不一致 0 |
| 実機 | `docs/checklist.md` | USB の認識、モーターの回転方向、エンコーダの符号、把持力の測定、非常停止、タイムアウト停止 |
